## 1. 产品定位

**费曼实验课 —— 每天 10 个话题，随机抽一个，裸讲一遍，让千问当那个"听不懂的外行"给你打分。**

不是知识点学习 App，是**输出倒逼输入的理解力训练器**。

### 1.1 产品名与调性

**名称：费曼实验课**

选择理由与调性：
- **"实验"**：契合费曼学习法的本质——讲错不是失败，是拿到了实验数据，修正后再来一轮。降低用户的挫败感
- **"课"**：有节奏感、有周期，对应每日一练 + 结业产出的课程化体验
- 与"打卡工具"形成差异：这里不是记录你有没有学，而是**检验你有没有真懂**

**Slogan 候选：**
1. 讲不明白，就是没搞懂
2. 每天一个实验，检验你的理解
3. 把知识讲给外行听

**UI 隐喻（供设计沿用，保持全站一致）：**

|---|---|
| 首页 / 练习入口 | 实验台 |
| 话题推荐列表 | 今日课题 |
| 裸讲输入页 | 第一次讲述 / 第二轮讲述 |
| 评价结果页 | 实验报告 |

| 卡点统计 | 卡点地图 |

## 2. 目标用户与核心场景

| 用户 | 场景 | 痛点 |
|---|---|---|
| 备考学生 | 每天碎片时间练一个概念 | 以为懂了，一讲就露馅（解释性深度错觉） |
| 职场新人 | 快速上手新业务/新领域 | 学了就忘，无法用自己的话复述 |
| 内容创作者 | 找选题 + 练表达 | 缺少"讲给外行听"的反馈回路 |
| 泛学习者 | 把生活经验结构化 | 没有体系化的自我检验工具 |

## 3. 理论依据（来自需求方提供的两张图）

### 3.1 评价准则 —— 四步核心
1. **选定目标**：明确要讲的概念
2. **讲给小孩**：不查资料先裸讲一遍（用语简单、无行话）
3. **定位卡点**：圈出讲不通、含糊、绕圈子的地方
4. **简化打磨**：针对卡点补课后重讲，直到流畅

### 3.2 训练流程 —— 7 天节奏（本产品压缩为"单次会话内多轮迭代"）
裸讲 → 标卡点 → 补课 → 重讲（含原创比喻）→ 外行测试 → 300 字小科普输出

### 3.3 设计原则
- 底层规律：**合意困难（desirable difficulty）+ 生成效应** —— 所以 AI 只给卡点和方向，**绝不给现成答案**
- 输出形式：口头讲述 / 手写白纸 / AI 对话 / 公开发布 —— 本产品主打 **语音口头讲述 + AI 对话 + 公开输出**

## 4. 功能需求

### F1 话题推荐系统（P0）

| 项 | 说明 |
|---|---|
| **底库（默认）** | **1000 条常青话题底库**，6 大类各约 160 条：科学常识 / 经济金融 / 技术概念 / 人文社科 / 生活经验 / 职场方法。每条字段：标题、一句话背景、难度标签、3 个引导问题、分类、关键词标签 |
| **实时热榜（增量）** | 后端定时任务（每小时）聚合热榜：微博热搜、知乎热榜、百度热搜、抖音热点。经**学习价值过滤**（剔除纯娱乐/八卦/时政敏感）后入池，打"热榜"标识，**72h 后自动降权** |
| 每日推荐 | 每天 0 点生成当日课题 **10 条** = 6 条底库（按偏好/历史薄弱项抽）+ 4 条热榜（过滤去重后） |
| 随机抽取 | 点"开始随机实验"从当日 10 条抽 1 条；支持"换一个"（每日 3 次） |
| 去重 | 已练话题 30 天内不重复推送 |
| 话题详情 | 一句话背景 + 3 个引导问题（热身，不给答案） |
| 难度分层 | 入门 / 进阶 / 硬核，用户可设偏好 |
| 运营后台 | 话题增删改、热榜过滤白/黑名单、分类与难度维护 |

### F2 费曼练习流程（P0，核心闭环）

```
选课题 → ①裸讲（打字/语音） → 千问评价(四维+卡点+等级) → ②修正重讲 → 再评价
            ↑__________________循环（≤5轮）__________________|
                     ↓ 等级达到 良及以上 → 结业：生成实验产出
```

| 步骤 | 说明 |
|---|---|
| ① 裸讲 | 用户**不查资料**，用自己的话讲清课题。**两种输入**：打字 / **语音输入**（见 F2.1）。首次讲述提示"可以先胡说，随便讲"降低启动门槛 |
| ② AI 评价 | 千问以"费曼四步准则 + 外行听众"双角色评价，输出见 F3 |
| ③ 修正重讲 | 依据卡点反馈修正后重新讲，历次版本可对比回看；上限 5 轮/次 |
| ④ 结业 | 等级 ≥ 良 → 通过；生成 **300 字小科普**，可导出文字/MD/图片并分享（见 F4） |
| 补课提示 | 每轮附"卡点补课建议"（该查什么、关键词是什么），但**不给答案** |
| 中断恢复 | 中途退出保留草稿，下次进入可选择"继续上一轮" |

#### F2.1 语音输入（P0，两端都要）

| 端 | 方案 | 体验要求 |
|---|---|---|
| Web | 优先浏览器 `Web Speech API`（实时转写边说边出字）；不支持的浏览器降级为**录音上传 → 后端 ASR**（通义） | 实时上屏、停顿不丢字、可手动编辑 |
| Android | 原生录音（uni-app `plus.audio` / RecorderManager）→ 上传 ASR，或调用系统语音识别 | 支持后台录音、断网本地缓存待上传 |

**通用要求：**
- 转写结果**落在输入框可编辑**，不是只读文本（防 ASR 错字坑评分）
- 录音波形 + 时长可视；单次上限 5 分钟
- 语音时长与最终字数共同计入"裸讲完成度"（防敷衍）
- **语音原文与最终提交文本分字段存储**，便于回看"我当时怎么讲的"

### F3 评价体系（P0）—— 通义千问驱动

**模型与接入：**

| 用途 | 模型 | 说明 |
|---|---|---|
| 主评价 | `qwen-plus` | 性价比与稳定性平衡，日常走它 |
| 复评 / 争议结果 | `qwen-max` | 用户申请复评，或边界分自动复评 |
| 结业小作文 | `qwen-plus` | 基于**用户自己的讲述内容**润色成 300 字科普，禁止凭空生成 |
| ASR | 通义语音识别（Paraformer）/ 通义听悟 | 语音转文字 |
| 调用方式 | DashScope **OpenAI 兼容模式**（`/compatible-mode/v1`） | 后续换模型只改配置 |
| Key 管理 | 仅后端环境变量 / 配置文件持有，**绝不进前端、不入库明文** | API Key 已具备 ✅ |

**四个评分维度（各 25 分，满分 100）：**

| 维度 | 费曼准则对应 | 千问判定要点 |
|---|---|---|
| 简洁性 | 讲给小孩听得懂 | 无未解释术语/行话；句子直白，无堆砌 |
| 完整性 | 概念讲通 | 是什么 / 为什么 / 怎么用 三要素覆盖 |
| 逻辑性 | 讲得通 | 无自相矛盾、无循环论证，因果链清晰 |
| 比喻力 | 原创比喻 | 有无生活化类比；贴切加分，不当类比扣分 |

**等级映射（良为及格线）：**

| 等级 | 分数 | 是否及格 |
|---|---|---|
| 优 | 85–100 | ✅ 及格，直接结业 |
| 良 | 70–84 | ✅ 及格（70–74 提示"再修一轮可冲优"） |
| 中 | 50–69 | ❌ 不及格，继续修正 |
| 差 | 0–49 | ❌ 不及格，建议先补课再重来 |

**评价输出（结构化 JSON，前端渲染）：**
1. 外行视角总评一句话（"作为完全不懂的人，我听懂了吗"）
2. 四维度雷达图 + 得分
3. 卡点清单（逐条**引用原文片段**，标注"哪里讲不通、为什么"）
4. 修正建议（只给方向，不给答案）
5. 本轮等级 + 与上轮对比（进步点 / 退步点）

**评分一致性保障：**
- 固定评分 rubric 写进 System Prompt，`temperature=0.2`
- 边界分（68–72）自动触发**二次评价取中**，避免一次评差就劝退
- 每次评价记录 **prompt 版本号**，便于回归对比与调优
- JSON 解析失败自动重试一次，仍失败则降级提示

### F4 结业产出与分享（P0）

等级达"良"及以上后进入**实验产出页**，三种产出形态：

| 产出 | 内容 | 技术实现 |
|---|---|---|
| **纯文字** | 300 字小科普正文 | 一键复制到剪贴板 |
| **Markdown 文档** | `.md` 文件，含标题、正文、等级徽章、四维得分、话题标签、日期 | 前端拼字符串 → Blob 下载；Android 存本地后走系统分享 |
| **图片卡片** | 竖版分享卡 **1080×1440**：课题名 + 300 字正文 + 等级徽章 + 四维雷达图 + 打卡天数 + 品牌水印短链 | Web：Canvas / `html-to-image`；Android：Canvas 绘制后存相册 |

**分享能力：**
- **Web**：`navigator.share`（移动浏览器原生分享）+ 降级"复制链接 / 复制图片 / 下载图片"
- **Android**：系统分享面板（微信 / 朋友圈 / 微博 / QQ / 保存相册）
- **水印**：卡片右下角固定「费曼实验课」+ 日期，便于传播回流
- **隐私**：分享内容默认**只含科普正文与等级**，不含原始裸讲稿

### F5 实验记录本与成长（P1）

- 练习历史：课题、日期、轮次、最终等级、耗时
- 进步曲线：近 30 天等级趋势、平均修正轮次（轮次下降 = 进步）
- 卡点地图：高频卡点类型统计（术语依赖 / 逻辑断裂 / 缺比喻 / 要素缺失）
- 课题合集：已练课题，可回看每轮版本对比（v1 裸讲 vs 结业版）

### F6 每日推送与打卡（P1）

- Android 每日 09:00 推送"今日 10 个课题"（可自定义时间 / 关闭）
- 两端首屏展示今日课题 + 连续实验天数

## 5. 双端规划（Android 测试通过即上线）

| | Web 端 | Android 端 |
|---|---|---|
| 定位 | 主创作端：长文输入、大屏雷达图、记录与导出管理 | 移动主入口：抽题、语音裸讲、推送、一键分享 |
| 技术 | Vue3 + Vite | **uni-app（Vue3）**，复用业务逻辑与 API 层，一套代码可延伸小程序 |
| 输入 | 键盘 + 语音（Web Speech API / 上传 ASR） | 语音为主（原生录音）+ 键盘 |
| 产出 | 复制 / 下载 .md / 下载图片 / Web Share | 系统分享面板 / 存相册 / 存文件 |
| 上线 | 先出可用版本 | **功能测试 + 真机兼容测试通过后即上线**，与 Web 同期对外，不分期搁置 |

**共享后端**（P0）：话题服务（底库 + 热榜聚合）+ 评价服务（千问）+ ASR 服务 + 用户/记录服务，两端同一套 REST API。

## 6. 技术要点

- **千问接入**：DashScope OpenAI 兼容端点；评价走 JSON 结构化输出 + 严格 schema 校验
- **热榜爬取**：定时任务（每小时）拉各平台热榜 → 学习价值打分（关键词白/黑名单 + 千问轻量筛选）→ 入池 → 72h 降权
- **1000 条底库**：由千问批量生成 + 人工校验（每类约 160 条）→ CSV/JSON 导入
- **数据模型**：
  - `topic`（课题：标题/背景/分类/难度/引导问题/来源/权重）
  - `practice`（一次实验：用户/课题/轮次数/最终等级/耗时）
  - `round`（一轮讲述：文字原文 OR 语音URL + ASR文本 + 评价JSON + 等级 + prompt版本）
  - `user`（账号/偏好/打卡）
- **成本控制**：评价输入长度截断（超 1500 字提示精简）；同话题同文本 24h 内命中缓存不重复调模型
- **风控**：用户输入与 AI 输出双向内容安全过滤；热榜源屏蔽时政/敏感类
- **稳定性**：千问接口超时降级（提示"评价服务繁忙，你的讲述已保存"），讲述内容本地暂存不丢

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 千问评分忽高忽低，用户觉得不公平 | 固定 rubric + `temperature=0.2` + 边界分二次评价取中 + prompt 版本追踪 |
| 热榜娱乐词太多，偏离学习定位 | 底库为主（6:4）、热榜为辅 + 学习价值过滤 + 72h 降权 |
| 语音识别错字影响评分 | 转写结果可编辑后再提交；ASR 原文与最终文本分字段存 |
| 用户三句话敷衍交差 | 最低字数/时长门槛（80 字 或 30 秒）+ 千问识别"敷衍讲"直接判差 |
| 多轮迭代劝退 | 中/差轮次给增量进步点反馈；卡点只给方向不给答案 |
| 分享卡传播无回流 | 卡片固定带品牌名 + 短链，可追踪来源 |
