# 费曼学习法精进工具 · 产品需求文档（PRD v0.1）

> 作者：搭档⚡（产品视角初稿）　|　日期：2026-09-28　|　状态：待评审

---

## 1. 一句话定位

**每天 10 条热门话题，随机抽一个，用"费曼式裸讲 → AI 评价 → 修正重讲"的循环逼你真正搞懂一个概念。**

不是知识点学习 App，是**输出倒逼输入的理解力训练器**。

---

## 2. 目标用户与核心场景

| 用户 | 场景 | 痛点 |
|---|---|---|
| 备考学生 | 每天碎片时间练一个概念 | 以为懂了，一讲就露馅（解释性深度错觉） |
| 职场新人 | 快速上手新业务/新领域 | 学了就忘，无法用自己的话复述 |
| 内容创作者 | 找选题 + 练表达 | 缺少"讲给外行听"的反馈回路 |
| 泛学习者 | 把生活经验结构化 | 没有体系化的自我检验工具 |

---

## 3. 产品依据（来自用户提供的两张图）

### 3.1 评价准则 —— 四步核心
1. **选定目标**：明确要讲的概念
2. **讲给小孩**：不查资料先裸讲一遍（用语简单、无行话）
3. **定位卡点**：圈出讲不通、含糊、绕圈子的地方
4. **简化打磨**：针对卡点补课后重讲，直到流畅

### 3.2 训练流程 —— 7 天节奏（本工具压缩为"单次会话内的多轮迭代"）
- 裸讲 → 标卡点 → 补课 → 重讲（含原创比喻）→ 外行测试 → 300 字小科普输出

### 3.3 设计原则
- 底层规律：合意困难（desirable difficulty）、生成效应
- 输出形式：口头讲述 / 手写白纸 / AI 对话 / 公开发布 —— 本工具主打 **AI 对话 + 公开输出**
- 适用场景：学习新知、上手新业务、消化生活经验、用好 AI

## 4. 功能需求

### F1 话题推荐系统（P0）

| 项 | 说明 |
|---|---|
| 话题来源 | 热门话题/热词库：微博热搜、知乎热榜、百度热搜（后端定时聚合，T+1h 更新）+ 运营精选常青概念库（如"通货膨胀""闭包""MVP"） |
| 每日推荐 | 每天固定生成 **10 条**，展示当日榜单 |
| 随机抽取 | 用户点"随机一个"，从当日 10 条（或全量话题池）随机抽 1 条进入练习 |
| 去重 | 已练过的话题 7 天内不重复推送；练习历史可重抽 |
| 话题详情 | 每条话题附：一句话背景简介 + 3 个引导问题（帮用户热身） |
| 难度分层 | 话题打标签：入门/进阶/硬核，用户可选偏好 |

### F2 费曼练习流程（P0，核心闭环）

```
选话题 → ①裸讲 → AI评价(标卡点) → ②修正重讲 → 再评价
              ↑__________________循环__________________|
                        ↓ 等级达到 良及以上 → 结业：生成300字小科普
```

| 步骤 | 说明 |
|---|---|
| ① 裸讲 | 用户**不查资料**，用自己的话输入对这个话题的理解（文字为主，支持语音转文字） |
| ② AI 评价 | AI 以"费曼四步准则 + 外行听众"双角色评价，输出见 F3 |
| ③ 修正重讲 | 用户根据卡点反馈修正，重新提交；支持多轮（上限 5 轮/次） |
| ④ 结业 | 等级 ≥ 良 → 通过；引导生成 **300 字小科普**（对应 Day7 公开输出），可一键复制/分享 |
| 补课提示 | 每轮评价附"卡点补课建议"（需要查什么资料、哪些关键词） |

### F3 评价体系（P0）

**四个评分维度（每项 25 分，满分 100）：**

| 维度 | 费曼准则对应 | AI 判定要点 |
|---|---|---|
| 简洁性 | 讲给小孩听得懂 | 无未解释术语/行话；句子直白 |
| 完整性 | 概念讲通 | 是什么/为什么/怎么用 三要素覆盖 |
| 逻辑性 | 讲得通 | 无自相矛盾、无循环论证、因果链清晰 |
| 比喻力 | 原创比喻 | 有无生活化类比；类比是否贴切（贴切加分，牵连扣分） |

**等级映射：**

| 等级 | 分数 | 是否及格 |
|---|---|---|
| 优 | 85–100 | ✅ 及格，可直接结业 |
| 良 | 70–84 | ✅ 及格（含勉强边界：70 分处建议"可再修一轮"） |
| 中 | 50–69 | ❌ 不及格，继续修正 |
| 差 | 0–49 | ❌ 不及格，建议先看补课资料再重来 |

**评价输出格式：**
1. 总评一句话（外行听众视角："我听懂了吗"）
2. 四维度雷达图 + 得分
3. 卡点清单（逐条引用原文，标注"哪里讲不通、为什么"）
4. 修正建议（不给答案，只给方向 —— 保留生成效应）
5. 本轮等级

### F4 学习记录与成长（P1）

- 练习历史：话题、日期、轮次、最终等级
- 成长曲线：近 30 天等级趋势、平均轮次（轮次下降 = 进步）
- 卡点词云：高频卡点类型统计（术语依赖 / 逻辑断裂 / 缺比喻）
- 话题库：已练话题合集，可回看历次版本对比（v1 裸讲 vs 结业版）

### F5 每日推送（P1）

- Android 端每日 09:00 推送"今日 10 条话题"
- Web 端登录首屏展示今日榜单 + 连续练习天数（打卡激励）

### F6 分享/公开输出（P2）

- 结业的小科普生成分享卡片图（含等级徽章、雷达图）
- 对接：复制文本 / 保存图片 /（后续）社区广场

## 5. 双端规划

| | Web 端（先行） | Android 端 |
|---|---|---|
| 定位 | 主创作端：长文输入、大屏看雷达图、历史管理 | 碎片场景：抽话题、短讲、推送、打卡 |
| 技术 | Vue3 + Vite（沿用现有技术栈习惯） | uni-app（Vue3 语法复用）或原生，待定 |
| 输入 | 键盘长文（500–1000 字） | 语音转文字优先 |
| 账号 | 同一账号体系，云端同步练习记录 | 同左 |

**共享后端**（P0）：话题聚合服务 + AI 评价服务 + 用户/记录服务，两端走同一套 REST API。

---

## 6. 技术要点（初步）

- **AI 评价**：LLM 结构化输出（JSON：四维得分 + 卡点数组 + 等级 + 建议），配 Prompt 固定评分 rubric，保证等级一致性（同输入多次评价波动 ≤ 一档）
- **话题热榜**：后端定时任务聚合各热榜 API + 独立常青概念库（避免热榜全是娱乐词），运营可后台增删话题与难度标签
- **数据模型**：topic（话题）/ practice（一次练习）/ round（一轮裸讲：原文+评价JSON+等级）/ user
- **风控**：AI 评价输出需内容安全过滤；用户输入做敏感词过滤

---

## 7. MVP 范围与里程碑

| 阶段 | 内容 |
|---|---|
| **M1（MVP）** | Web 端：话题池（预置 200+ 常青话题）→ 随机抽题 → 裸讲 → AI 评价（四维+等级+卡点）→ 多轮修正 → 及格结业出 300 字科普。无账号，localStorage 存记录 |
| **M2** | 账号体系 + 云端记录 + 成长曲线 + 卡点词云；Android 端（uni-app）跑通核心流程 |
| **M3** | 热榜聚合实时话题 + 每日推送 + 分享卡片 + （可选）公开社区 |

---

## 8. 关键指标（北极星）

- **周及格话题数**：每周达到"良"及以上的话题数量（衡量真实理解产出）
- 辅助：平均修正轮次（越少越好）、7 日留存、结业科普分享率

---

## 9. 待确认问题（需要你拍板）

1. **AI 评价用哪家的模型/Key？**（决定成本与评分稳定性）
2. **话题来源**：MVP 先用预置常青话题库，还是一开始就接真实热榜爬取？
3. **Android 优先级**：M2 才做，还是有上线时间硬要求？技术选型 uni-app 还是原生？
4. **裸讲形式**：MVP 仅文字，语音转文字是否必须进 M2？
5. **"良"的边界**：70 分卡线时，是直接放行，还是强制提示"建议再修一轮"？
6. **产品名**：需要一个名字（候选：费曼打卡 / 讲明白 / 裸讲实验室）。

## 10. 风险

| 风险 | 对策 |
|---|---|
| AI 评分忽高忽低，用户感觉不公平 | 固定 rubric + 双次评价取中 + 温度调低 |
| 热榜娱乐词太多，偏离"学习"定位 | 常青概念库为主、热榜为辅 + 白名单过滤 |
| 用户输入三句话就交差 | 最低字数门槛（如 80 字）+ AI 检测"敷衍讲"判差 |
| 多轮迭代劝退，中差挫败感强 | 卡点反馈给方向不给答案；中/差轮次给"你比上轮进步点"式增量反馈 |
